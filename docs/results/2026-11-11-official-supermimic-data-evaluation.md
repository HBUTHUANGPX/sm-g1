# Official/local data and evaluation audit

Read-only source audit: official `official checkout` (5efbf114); local `local checkout` (83120bf). Below `O/` means official root; `L/` local root; `P/` means local `mimic_baseline/source/mimic_baseline/mimic_baseline/tasks/supermimic/`. This audits active ManagerBased modules, not removed standalone code. No simulation or numerical equivalence test performed.

## Principal findings

1. **High: goal conditioning and temporal horizon materially differ.** Official `O/src/supermimic/representations.py:96-106,173-200` uses 10 frames at offsets [0,5,...,45], raw joint positions and velocities; `:203-234` computes reference anchor pose relative to *current robot root*. `O/src/supermimic/tasks/env_cfgs.py:145-159` includes anchor position only for the world model, anchor orientation for actor and WM. Local active command `P/envs/mdp/commands.py:358-359,413` requests 10 frames through ReferenceBatch; `P/data/reference.py:62-95,142-159` uses offsets [1,...,10], root translation relative to current *reference* root and reference yaw frame, reference rotation, reference-local linear/angular velocity, joints and 0.1-scaled joint velocity. G1 gives 73 features/frame (15+2*29), not the stale 69-D/27-joint comments in `P/data/motion.py:393-398` or command docstring. At the stated 50 Hz these represent next 0.02–0.20 s locally versus current through 0.90 s officially. This is a different policy information contract, not just coordinate renaming; the 730-D goal is reference-only, but the active actor also receives a separate 6-D current robot/reference orientation in its decoder (`P/runtime/configuration.py:40-42`, `P/learning/models.py:460-479,527-537`). Thus the whole actor is not deprived of robot-relative reference feedback; its information contract still differs.

2. **High: reset curriculum is a different algorithm.** Official default is return sampling (`O/src/supermimic/runners/supermimic_runner.py:88-93,574-644`), with gamma .99, 20-step windows, memory 256, steepness 25, explore .5 and keep .1 (`O/src/supermimic/runners/reset_sampling.py:17-34`). Falls bootstrap zero; clip-end bootstraps mean V; timeout next-bin V (`:98-120`); focus is softmax(-25 V/Vmax), keep is accumulated squared focus (`:147-153`). Local active command instantiates MasterySampler (`P/envs/mdp/commands.py:96`); evidence is full uninterrupted 25-transition bin quality, termination zero even on partial entry, nonfailure partial exits excluded (`P/data/sampling.py:58-75,152-184`). Default update interval is 2^20 real transitions (`:78-80,186-191`); weights use (1-mastery)^2 with 5% uniform, change-rate bounds and cap (`:217-228`), sampled frame is bin start with probability .5 otherwise uniform offset (`:233-244`). These change training distribution and should be separate experimental variables, not assumed interchangeable implementations of adaptive sampling.

3. **High: data/robot/FK parity cannot be established from the supplied official checkout.** Official README `O/README.md:14-20` requires sibling mjlab_research. `O/src/supermimic/tasks/env_cfgs.py:12-13,162-166` inherits G1 config/MotionCommand; `O/src/supermimic/representations.py:493-495` reuses MotionLoader FK. Therefore inherited body/joint ordering, robot geometry, motion loader conversion and resampling behavior are outside this checkout. Parent audit reports dependency fetch unavailable; do not substitute a similarly named public mjlab checkout as proof. Official training defaults to W&B `lafan_run1_subject5` (`O/src/supermimic/scripts/train.py:30-31`), with optional local globs/comma lists delegated to MotionLoader (`:61-74`). There is no basis here to claim the same pinned dataset, preprocessing, joint mapping, or all-40 training set as local.

4. **High for result interpretation: local strict/full_clean results are not official benchmark results.** Official README offers training/playback (`O/README.md:23-42`), not an all-40 tracking evaluation protocol. Official `scripts/benchmark.py` expressly times simulation/world-model throughput; `:101-134` resets then times steps, discards step reward/done values, reports steps/s, and even repeats current sensor to pad history for timing (`:117-118`). Local `P/evaluation/profiles.py:9-25,51-99` disables reset noise/randomization, checks realized nominal context and corruption, preserves strict native termination (height, tilt, motion_end,time_out and recovery ankle/wrist), while full_clean requires zero delay and no termination. Local `P/evaluation/rollout.py:94-99,130-136,257-288,344-378` selects original endpoints, starts trials from clip starts, accumulates actual transitions, stops strict at termination and declares full_clean tracking_success null. Coverage must not be called tracking success, nor compared numerically to an official result without an aligned protocol.

## Local data/kinematics details that must be preserved in a controlled comparison

- `L/tools/assets/download_lafan1.py:9-10,39-47`: dataset revision ce1572906efe6157840e8474d5a0d7aa87481e74; exactly 40 root g1 CSVs plus matching robot description. Existing nonempty downloads are skipped (`:18-21`); revision URL is pinned, but downloader does not independently verify existing content hash. Converter records consumed CSV SHA256 (`P/data/lafan1.py:59,72-88`). This supports content lineage, not proof that an existing file matches the pinned remote blob.
- `P/data/lafan1.py:1-6,19-60`: finite [T>=2,36] CSV, root xyz metres, xyzw->wxyz quaternion normalization; 30->50 Hz linear position/joint interpolation and quaternion SLERP; derivative velocities via torch.gradient and SO(3) finite differences; stores only pelvis body with world velocities and ordered 29 joint names. Last output frame is floor-based, never extends beyond source duration. Official preprocessing not supplied; do not assert its derivatives or resampling match.
- `P/data/motion.py:207-224,234-245`: maps joints and root by names; accepts xyzw metadata conversion; root data only taken from NPZ. `:247-287`: rounds each training clip to 25-transition bins, repeats terminal pose with zero velocities, retains original length/end for evaluation. `:298-322`: recomputes tracked-body transforms and velocities from URDF FK in double at load then stores float. It does not trust imported nonroot body arrays. Both pipelines clamp future windows within a clip, but official clamps to MotionLoader end (`O/.../representations.py:178-189`), local training to its padded catalog end (`P/data/reference.py:142-159`). Therefore terminal reference samples can differ even with matching raw data.
- `P/robots/g1/kinematics.py:12-57,62-80`: explicit 29 joint names, 14 tracked bodies including pelvis, pelvis root, recovery torso/ankle/wrist groups; adapts shared URDF parser. Fixed links participate in local FK. Official GenCoord FK delegated to MotionLoader; MaxCoord builds AnalyticIK using simulator body IDs, joint q addresses and motion body indices (`O/src/supermimic/representations.py:642-653`). MaxCoord is another representation, not equivalent to local generalized state merely because both track bodies.

## Metric interpretation

`P/evaluation/metrics.py:22-35`: normalized return divides by max-step reward times original clip duration unless explicit duration_steps supplied. `:38-58`: root XY squared Euclidean distance, root Z squared error, SO(3) acos-angle squared, mean squared joint error, and body error terms supplied by MDP. `P/evaluation/rollout.py:257-264,390-391` accumulates only active trial steps then square-roots mean. Thus strict early failures have tracking errors measured on executed prefix, while coverage/return capture failure duration; do not compare their RMSE alone against full-clean whole-clip RMSE as policy improvement. Reward-normalized return also is implementation-specific, not a shared official accuracy unit.

## Claims and attribution

Official README only claims a SuperTrack implementation built on mjlab, two G1 representation tasks, training and play; it does not claim the supplied tree includes LAFAN retarget tooling, a complete dataset, or an all-40 evaluation suite. Its Apache-2.0 statement and inspirations are at `O/README.md:44-56` (ControlVAE BSD-3-Clause, robotic_world_model Apache-2.0, DreamerV3 MIT). Local `P/NOTICE:1-8` explicitly attributes unofficial supermimic_vibed 27126b... MIT and describes RX-P2/PhysX adaptation; this final description is stale for the new G1/Newton path, but remains evidence of actual local provenance. `L/README.md:38-42` separately explains historical standalone provenance, active original managers/Trainer reuse, and separate dataset/robot terms with no data/checkpoint distribution. Do not label local code as an official Apache-licensed implementation simply because the paper or project name matches; preserve applicable MIT notices and add official attribution only for actual imported official material. Downloader selects CSV/robot subtree/ground (`L/tools/assets/download_lafan1.py:39-50`), not top-level dataset card/license; local README links dataset terms but download outputs alone should not be assumed to contain complete attribution.

## Recommended controlled alignment (no edits made)

First obtain exact official dependency revision and motion artifacts, export robot joint/body maps and fixed transforms, compare root convention, derivatives and FK numerically on identical source clips. Then independently align goal features/horizon and sampler; retain each as explicit ablation, not a bundled migration. Finally run the same checkpoint-policy interface under a documented matching evaluation protocol, reporting clip identities/original durations, delay/noise, termination, per-clip coverage and errors. Until then evidence supports source-level semantic differences, not causal performance claims or runtime equivalence.
